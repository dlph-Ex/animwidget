## 判断标准（以后什么时候该再动它）

一条进技术底座的条件是「**外人看不到、但决定了这个 App 能做到什么**」：

- 看得见的 UI 细节（图标长什么样）→ 不进；
- 实现手段（自己写解码器 / 反编译复刻 / 设备标定 / 静态门禁）→ 进。

所以以后新增这类东西时同步加一条：目前想到的候选是「画布无关帧预热」与「URI 推送的
缓存写盘策略」，但两者都还在调，等稳定了再写进底座。
