# 帧工坊 · FrameSmith

> 源码状态：v1.1.1 ~ v1.3.1 的原始源码曾丢失并已反编译修回，现在 **`src-v2/` 是自维护的 Java 源码树**
> （`scripts/build-apk-src.sh` 一条命令出包，不再依赖任何逆向产物）。恢复过程见 [RECOVERY.md](RECOVERY.md)、
> [RECOVERY-PLAN.md](RECOVERY-PLAN.md)。下面「代码结构」表格里的 `.kt` 文件名是历史名，对应现在 `src-v2/` 下的 `.java`。

把 **MP4 / GIF / 图片** 做成桌面小部件。每个组件独立配置：素材、帧率、清晰度、压缩质量、形状蒙版、不透明度、边框。

- 多实例：有几个桌面组件就有几套配置，互不影响
- 形状蒙版：24 种（方形 / 圆角 / 超椭圆 / 圆形 / 椭圆 / 胶囊 / 菱形 / 三角 / 星形 / 心形 / 水滴 / 盾形 …），**填满所选布局区域**，支持不透明度、细边框与可调阴影
- 布局：原始比例 / 填充 / 16:9 / 4:3 / 1:1 / 9:16 / 21:9；等比例缩放 0–100%（可键盘输入）
- 手势微调：**调整蒙版位置**（整块蒙版连同画面在组件内平移）与**调整内容位置**（画面在蒙版内平移 + 等比例缩放），互不干扰，每个组件独立保存
- 图片支持，压缩质量 50–100 无级可调
- 帧率 1–50 fps、清晰度 120–1920 px（8 px 一档）
- 可选 Shizuku 集成：一键把 App 加进 Doze 白名单、standby bucket、放宽后台 AppOps
- 无网络权限、无广告、无统计；浅色 UI，无深色模式
- `minSdk 26` / `targetSdk 34`，Kotlin + 平台 API（Shizuku 为可选依赖）

## 它怎么工作

安卓小部件由启动器进程通过 `RemoteViews` 渲染，只支持 `TextView` / `ImageView` 等少数控件，
没有 `SurfaceView` / `VideoView`，不能直接播放视频。所以：

1. 导入时把视频/GIF/图片解码成 WebP 帧（图片只有 1 帧）；
2. 播放服务用单个 `HandlerThread`（DISPLAY 优先级）轮询所有实例，
   每个实例各自记录帧号与下一次更新时间；
3. 每帧先按小部件尺寸采样解码 → 等比例缩放 → 按布局裁剪 → 套形状蒙版（含阴影 / 边框）→ 推给启动器。

所有形状合成在 App 侧完成（`FrameComposer` 唯一实现，导出与预览共用），因此任意形状、透明度、边框、阴影都能显示。

## 使用

1. 打开 App →「新建组件」→ 启动器会请求添加小部件并打开配置页；
2. 在配置页里选视频 / GIF / 图片，调帧率、清晰度、质量、形状、不透明度、边框；
3. 保存后会立即出现在桌面；
4. 回到 App 可以编辑任意组件；每个组件独立；
5. 删除桌面小部件会同时清掉它的配置与帧文件。

推荐：**12–30 fps + 720 px**。

## 流畅覆盖层（60fps）

`AppWidget` 的每一帧都要走 Binder + 启动器重绘，帧率上限在 10–30 fps。要真正流畅，
可以给组件开启「流畅覆盖层」：在桌面上用悬浮窗播放，视频走 `TextureView + MediaPlayer`，
GIF 用 `Movie` 自绘，图片静态绘制，均按屏幕刷新率渲染。

授权（任选其一）：

```bash
adb shell appops set io.github.animwidget SYSTEM_ALERT_WINDOW allow
# 或者在系统设置 → 应用 → 显示在其他应用上层 里打开
```

使用：配置页勾选「流畅覆盖层（60fps）」→ 保存；或点「拖动调整位置 / 双指缩放」进入编辑模式，
拖动定位、双指缩放，点右上角 ✓ 保存。

已知限制：

- 覆盖层不是 AppWidget，不参与启动器排版，且会显示在所有应用上层。
- 非编辑状态是 `FLAG_NOT_TOUCHABLE`（完全穿透，不挡图标）；编辑状态才可触摸。
- 视频为矩形窗口；任意形状蒙版只对 GIF / 图片生效。
- 视频/GIF 直接读原始素材 URI，文件被删或权限失效时退回显示第一帧。

## 后台流畅度

「App 在前台才流畅」的根因是进程优先级与系统调度，不是帧率参数没生效。本项目做了：

- 前台服务（`specialUse` 类型）+ 常驻低优先级通知
- 渲染线程 `THREAD_PRIORITY_DISPLAY`（-4），比默认后台线程调度更及时
- 单线程调度多实例，减少线程切换与 Binder 竞争
- 息屏自动暂停，亮屏恢复
- 可在 App 内「加入电池白名单」

再加一层（可选，需要 Shizuku）：

- `cmd deviceidle whitelist +<pkg>`：Doze 白名单
- `am set-standby-bucket <pkg> active`：活跃 bucket
- `cmd appops set <pkg> RUN_IN_BACKGROUND allow` / `RUN_ANY_IN_BACKGROUND allow`

点「后台优化（Shizuku）」→ 授权 → 自动执行并显示每条命令的输出。
没装 Shizuku 或未授权时，这个功能只是不可用，不影响其它功能。

> 注意：50 fps 仍是「可设上限」。小部件每帧都要过 Binder 并让启动器重绘，
> 多数机器实际上限在 10–30 fps；这部分是平台约束。

## 构建

### Android Studio

直接打开本目录。依赖只有 Shizuku（可选功能）：

```kotlin
implementation("dev.rikka.shizuku:api:12.2.0")
implementation("dev.rikka.shizuku:provider:12.2.0")
```

### GitHub Actions

`.github/workflows/build.yml` 推上去自动出包。

### 手工打包（无 Gradle / aarch64）

```bash
# 需要 JDK 17、python3、aapt，以及：
#   Android SDK 的 platform android.jar、build-tools 的 d8.jar / apksigner.jar
#   Kotlin 编译器（kotlin-compiler-embeddable + kotlin-stdlib）
#   Shizuku 合并 jar：api + aidl + shared + provider 的 classes.jar 合并成一个
ANDROID_SDK=/tmp/sdk KOTLIN_LIBS=/tmp/kl SHIZUKU_JAR=/tmp/shizuku/shizuku-all.jar \
  ./scripts/build-apk.sh
```

`scripts/pack_apk.py` 负责把 `resources.arsc` 与 `classes.dex` 以未压缩且 4 字节对齐的
方式写进 zip（aapt1 不保证）。

## 代码结构

| 文件 | 作用 |
| --- | --- |
| `MainActivity.kt` | 组件列表、新建、编辑入口、Shizuku/电池优化 |
| `ConfigActivity.kt` | 单实例配置：素材、帧率、清晰度、质量、形状、透明度、边框、预览 |
| `MediaImporter.kt` | MP4 / GIF / 图片 → WebP 帧；限帧数、限体积、帧号重排 |
| `WidgetConfig.kt` | 配置模型与按 widgetId 的存储、采样解码 |
| `ShapeFactory.kt` | 8 种形状 Path + 蒙版/不透明度/边框合成 |
| `WidgetRender.kt` | 尺寸换算、等比裁剪、形状合成、RemoteViews 推送、帧缓存 |
| `PlaybackService.kt` | 多实例调度循环、日志、息屏暂停、前台通知 |
| `WidgetProvider.kt` | 小部件生命周期、首帧渲染、清理配置 |
| `ShizukuHelper.kt` | Shizuku 绑定/授权/执行 shell 命令（可选） |

## 已知限制

- 高帧率仍受启动器与 Binder 限制，50 fps 是上限而非保证。
- 形状不支持旋转（按需求未实现）；形状本身包含椭圆、斜向等预设。
- 删除配置不会自动移除桌面上的小部件，需要用户在桌面删除。
- 配置页预览使用 720 px 合成图，最终以小部件实际尺寸为准。
- Shizuku 使用 12.2.0 客户端 API；若设备上的 Shizuku 服务端过新/过旧，
  命令可能执行失败，App 会把错误原样显示出来。
- 后台仍可能被激进 ROM 清理；建议同时加入电池白名单。
